# Установка scrcpy master

Инструкция проверена на Linux Mint (Cinnamon), scrcpy 1.25.

## 1. Системные зависимости

```bash
sudo apt update
sudo apt install python3 python3-venv python3-tk adb scrcpy
```

- `python3-tk` — обязателен, без него интерфейс не запустится вообще
  (даже в виртуальном окружении: Tk-биндинги подтягиваются из системы).
- `adb` и `scrcpy` можно не ставить через apt, если у вас уже есть свежие
  сборки в другом месте — тогда просто укажите полный путь к ним прямо в
  интерфейсе программы (поля внизу левой панели).
- Проверьте версию scrcpy: `scrcpy --version`. Эта сборка интерфейса
  рассчитана на **scrcpy 1.25** — в форме сознательно нет опций,
  появившихся только в 2.x (аудио, выбор видеокодека, камера — см.
  раздел «Ограничения» в README.md проекта).

## 2. Распакуйте проект

Скопируйте папку проекта (со всеми `.py`-файлами, `requirements.txt`,
`run.sh`, `scrcpy-master.desktop`) куда вам удобно, например:

```bash
mkdir -p ~/desktop/scrcpy
# переместите сюда все файлы проекта
cd ~/desktop/scrcpy
```

## 3. Виртуальное окружение (настоятельно рекомендуется)

Если на компьютере установлен Anaconda/Miniconda (в терминале виден
префикс `(base)`), **обязательно** используйте отдельный venv — иначе
зависимости могут встать в питон conda, а не в тот, что реально
используется при запуске через ярлык, и программа будет молча падать
при клике по значку, работая только из терминала.

```bash
cd ~/desktop/scrcpy
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
deactivate
```

`run.sh` сам находит и активирует `venv/`, если он лежит рядом с
`main.py` — больше ничего настраивать не нужно.

Без conda (обычный системный Python) можно проще, без venv:

```bash
pip install -r requirements.txt --break-system-packages
```

## 4. Первый запуск (проверка)

```bash
cd ~/desktop/scrcpy
python3 main.py            # если ставили без venv
# или
source venv/bin/activate && python3 main.py && deactivate   # если использовали venv
```

Должно открыться окно «scrcpy master». Если нет — см. раздел
«Диагностика проблем» ниже.

## 5. Ярлык запуска в меню Cinnamon

### 5.1. Сделайте `run.sh` исполняемым

```bash
chmod +x ~/desktop/scrcpy/run.sh
```

**Это самый частый источник проблем** — при копировании/скачивании
файла право на выполнение обычно слетает, и его нужно каждый раз
выставлять заново после того, как файл был перезаписан новой версией.

### 5.2. Пропишите правильный путь в `.desktop`-файле

Откройте `scrcpy-master.desktop` в текстовом редакторе и замените
строку `Exec=` на реальный путь к вашему `run.sh`:

```
Exec=/home/ВАШ_ЛОГИН/desktop/scrcpy/run.sh
```

Точный путь можно получить командой:

```bash
realpath ~/desktop/scrcpy/run.sh
```

### 5.3. Установите ярлык в меню

```bash
mkdir -p ~/.local/share/applications
cp scrcpy-master.desktop ~/.local/share/applications/ && \
  chmod +x ~/.local/share/applications/scrcpy-master.desktop
```

Обратите внимание: обе команды соединены через `&&` — если вставить их
одной строкой без переноса, но без `&&`, шелл может склеить аргументы
`cp` и `chmod` в одну команду и выдать ошибку `No such file or directory`.

### 5.4. Найдите программу в меню

Откройте меню Cinnamon (кнопка внизу слева) и начните печатать
«scrcpy» — ярлык «scrcpy master» появится сразу, без перезапуска
Cinnamon. По правому клику на найденном ярлыке можно выбрать «Добавить
в панель» или «Добавить на рабочий стол».

## 6. Диагностика проблем

### Ярлык/скрипт не реагирует на клик вообще

```bash
ls -la ~/desktop/scrcpy/run.sh
```

Если в правах нет `x` (например, `-rw-rw-r--`) — выполните
`chmod +x ~/desktop/scrcpy/run.sh` и попробуйте снова.

Если вы используете файловый менеджер Nemo и `run.sh` при двойном
клике открывается как текст вместо запуска — смените поведение:
**Правка → Настройки → вкладка «Поведение» → «Исполняемые текстовые
файлы»** → выберите «Спрашивать» или «Запускать исполняемые текстовые
файлы при открытии».

### Ярлык кликается, но окно программы не появляется

Это самый неприятный случай — ошибка нигде не видна, потому что
`Terminal=false` прячет вывод. `run.sh` пишет полный лог каждого
запуска в файл `run.log` рядом с собой:

```bash
cat ~/desktop/scrcpy/run.log
```

В конце будет видно, какой именно `python3` использовался, и точная
ошибка. Типичная находка:

```
ModuleNotFoundError: No module named 'customtkinter'
```

Это значит, что зависимости стоят не в том Python, который реально
использует `run.sh` при запуске из ярлыка (см. раздел 3 — обычно
конфликт с conda). Решение — создать `venv`, как описано выше: `run.sh`
всегда предпочитает `venv/`, если он есть, независимо от того, что
творится с системным `PATH`.

### Работает из терминала, но не из ярлыка/меню

Почти всегда означает разницу окружений: терминал загружает `.bashrc`
(там может быть активация conda, изменения `PATH` и т.п.), а ярлык —
нет. Проверить, какой `python3` увидит ярлык, можно прямо в логе
(`run.log`, строка `python3:`). Если это не тот интерпретатор, где
стоит `customtkinter` — используйте `venv` (раздел 3), это полностью
снимает зависимость от внешнего окружения.

## 7. Полезные команды adb (если пригодится отдельно от интерфейса)

```bash
adb devices -l                     # список подключённых устройств
adb -s <serial> tcpip 5555         # включить Wi-Fi-режим (нужен USB один раз)
adb connect <ip>:5555              # подключиться по Wi-Fi
adb pair <ip>:<port> <код>         # беспроводное сопряжение Android 11+, без USB
adb kill-server && adb start-server  # перезапуск adb-сервера при странностях
```

Всё это уже доступно из диалога «Wi-Fi…» в самом интерфейсе программы —
раздел приведён на случай, если понадобится сделать что-то вручную.
